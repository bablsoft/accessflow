AccessFlow — quick reference

AccessFlow is an open-source database access governance platform. It sits as a full query
proxy between people and the databases, warehouses, outbound APIs and CI/CD pipelines they
need, and enforces configurable AI analysis and human approval before anything runs. Every
decision and execution lands in a tamper-evident audit log.

The query lifecycle
  1. Submit — a user picks a datasource and writes a query. AccessFlow parses it before anything runs, and rejects what it cannot parse or what reads a table that user is not allowed to read.
  2. Analyse — if the datasource has AI analysis enabled, a model scores the query for risk and explains what it does. Status: PENDING_AI.
  3. Route — the query can be approved without a human: by a routing policy, or because the user already holds a standing time-bound grant that pre-approves it. Otherwise the datasource review plan decides who must approve. Status: PENDING_REVIEW.
  4. Approve — every stage of the approval chain must clear. Nobody can approve their own query, not even an admin. Status: APPROVED, REJECTED or TIMED_OUT.
  5. Execute — the proxy runs the query under masking, row-level security and row caps, and records the result. Status: EXECUTED or FAILED.

Rules that never bend
  - A user can never approve their own request, regardless of role.
  - Break-glass bypasses AI and review, but only for someone holding the break-glass permission on that datasource; it pages every admin and opens a mandatory retro-review.
  - The audit log is insert-only — the application database role has no UPDATE or DELETE on it.
  - Datasource credentials are AES-256-GCM encrypted at rest and are never returned by any endpoint.
  - The help agent reads documentation only. It cannot see queries, results, audit rows, schemas or datasources, and it cannot act on your behalf.

Where things are in the app
  Screens are reached from the left sidebar, a two-level menu: a group heading, an optional
  collapsible sub-section, then the destination. Name a screen by the label below and give its
  menu path — "Workflow → Database → Query editor" — rather than its URL.

  The menu is filtered by permission. An entry appears only for someone holding one of the
  permissions listed with it, and a sub-section or group left with nothing visible is hidden
  entirely. Say which permission a destination needs rather than asserting it is in every
  reader's sidebar.

  Top of the sidebar (above the first group heading)
    Dashboard · /dashboard · needs QUERY_SUBMIT_SELECT — Personalized home: summary tiles, query trends, AI suggestions, weekly digest.
    Review queue · /reviews · needs QUERY_REVIEW, API_REQUEST_REVIEW or DEPLOYMENT_REVIEW — Everything waiting on your decision, in tabs for queries, API calls, deployments and rollbacks.

  Workflow → Database
    Query editor · /editor · needs QUERY_SUBMIT_DML — Pick a datasource, write a query, and submit it for review.
    Query history · /queries · needs QUERY_SUBMIT_SELECT — Queries the signed-in user submitted, with status and AI risk. A query admin sees the whole organization here.

  Workflow → API
    API Editor · /api-editor · needs QUERY_SUBMIT_DML — Compose a governed API call and submit it for review.
    API Requests · /api-requests · needs QUERY_SUBMIT_SELECT — API calls the user submitted, with status and AI risk.

  Workflow → Deployments
    Deployments · /deployments · needs QUERY_SUBMIT_SELECT — Deployment requests raised by CI/CD pipelines.
    Version Matrix · /deployment-versions · needs DEPLOYMENT_PIPELINE_MANAGE, DEPLOYMENT_REVIEW or QUERY_ADMIN — What version each environment is running, and where it has drifted.

  Workflow → Request groups
    Request Groups · /request-groups · needs QUERY_SUBMIT_SELECT — Grouped requests that bundle ordered query and API-call members.
    Group Reviews · /request-groups/reviews · needs QUERY_REVIEW — Review queue for grouped requests.

  Workflow → Access & lifecycle
    Request access · /access-requests · needs QUERY_SUBMIT_SELECT — Ask for access to a datasource, or track a request already made.
    Request erasure · /lifecycle/erasure · needs QUERY_SUBMIT_SELECT — Right-to-erasure requests over personal data.
    Erasure review · /lifecycle/erasure-reviews · needs ERASURE_REVIEW — Review queue for erasure requests.
    Attestation reviews · /reviews/attestations · needs ATTESTATION_REVIEW — Access recertification worklist: certify or revoke standing grants.

  Connections → Database
    Datasources · /datasources · needs DATASOURCE_MANAGE — Databases the user may query, and their connection health.
    Connectors · /admin/connectors · needs DATASOURCE_MANAGE — Connector catalog: engines available and their driver pins.
    Custom JDBC drivers · /admin/drivers · needs DATASOURCE_MANAGE — Uploaded JDBC driver JARs for custom engines.

  Connections → API
    API Connectors · /api-connectors · needs API_CONNECTOR_MANAGE — Governed outbound REST, SOAP, GraphQL and gRPC connectors.

  Connections → Deployments
    Deployment Pipelines · /admin/deployment-pipelines · needs DEPLOYMENT_PIPELINE_MANAGE — CI/CD pipelines, environments, freeze windows and permissions.

  Security & Access → Identity
    Users · /admin/users · needs USER_MANAGE — Create, deactivate and re-invite users; assign roles and permissions.
    Groups · /admin/groups · needs GROUP_MANAGE — User groups and the grants attached to them.
    Roles · /admin/roles · needs ROLE_MANAGE — Roles and the permissions each one carries.
    SAML / SSO · /admin/saml · needs SSO_CONFIGURE — SAML 2.0 single sign-on.
    OAuth providers · /admin/oauth2 · needs SSO_CONFIGURE — OAuth 2.0 / OIDC sign-in providers.
    SCIM Provisioning · /admin/scim · needs SSO_CONFIGURE — SCIM 2.0 provisioning tokens and attribute mapping.

  Security & Access → Access control
    Access requests · /admin/access-requests · needs ACCESS_REQUEST_REVIEW — Approve or reject incoming access requests.
    Review plans · /admin/review-plans · needs REVIEW_PLAN_MANAGE — Review plans: approval stages, approvers, timeouts, escalation.
    Routing policies · /admin/routing-policies · needs ROUTING_POLICY_MANAGE — Typed conditions that auto-approve, auto-reject or route a request.
    Over-provisioned access · /admin/over-provisioned-access · needs ACCESS_USAGE_REPORT_VIEW — Grants nobody has used, suggested for revocation.
    Break-glass log · /admin/break-glass · needs BREAK_GLASS_VIEW — Break-glass grants and the mandatory retro-review of each use.

  Security & Access → Data governance
    Data classifications · /admin/data-classifications · needs DATA_CLASSIFICATION_MANAGE — Classification tags and the masking they derive.
    Data Lifecycle · /admin/lifecycle/policies · needs RETENTION_POLICY_MANAGE — Data retention and erasure policies.
    Attestation · /admin/attestation · needs ATTESTATION_CAMPAIGN_MANAGE — Scheduled attestation campaigns over standing grants.

  Security & Access → Audit & compliance
    Audit log · /admin/audit-log · needs AUDIT_LOG_VIEW — The tamper-evident audit log, filterable and exportable.
    Audit sinks · /admin/audit-sinks · needs AUDIT_SINK_MANAGE — Where audit rows are streamed for long-term retention.
    Compliance reports · /admin/auditor · needs COMPLIANCE_REPORT_VIEW — Compliance reports and signed PDF / CSV exports.

  System
    Datasource health · /admin/datasource-health · needs DATASOURCE_MANAGE — Connection health across every registered datasource.
    Anomalies · /admin/anomalies · needs ANOMALY_MANAGE — User-behaviour anomalies the AI flagged.
    Notifications · /admin/notifications · needs NOTIFICATION_CHANNEL_MANAGE — Notification channels: email, Slack, webhooks, Discord, Telegram, Microsoft Teams, PagerDuty, ServiceNow and Jira.
    Slack · /admin/slack · needs NOTIFICATION_CHANNEL_MANAGE — Slack workspace connection.
    Languages · /admin/languages · needs LOCALIZATION_CONFIGURE — Which of the seven interface languages are offered.

  System → AI
    AI configurations · /admin/ai-configs · needs AI_MANAGE — AI providers: OpenAI, Anthropic, Ollama, OpenAI-compatible and Hugging Face for analysis; Voyage AI for embeddings only.
    AI analyses · /admin/ai-analyses · needs AI_MANAGE — History of every AI analysis, with tokens and latency.
    Langfuse · /admin/langfuse · needs AI_MANAGE — Langfuse tracing for AI calls.
    Help assistant · /admin/help-agent · needs AI_MANAGE — In-app help assistant: bind it to an AI provider, tune retrieval and retention, and re-index the bundled documentation.

  Platform
    Organizations · /admin/organizations · platform administrators only — Organizations (tenants) and their settings.

Screens with no menu entry
  / — Lands on the dashboard once signed in. Reached by: The application root — signing in arrives here.
  /queries/:id — One query: SQL, AI analysis, approval chain, results, audit trail. Reached by: Open a row in Query history, or follow the link in a notification.
  /reviews/:id/decide — Approve or reject one request. The decision is re-authenticated — it asks for your password or TOTP code. A comment is optional. Reached by: Follow the decision link in a review notification or push message.
  /request-groups/:id — One grouped request: its members, their order, and the aggregated approval. Reached by: Open a row in Request Groups.
  /request-groups/new — Build a grouped request and order its members. Reached by: The create action on Request Groups.
  /request-groups/:id/edit — Change a grouped request before it is submitted. Reached by: The edit action on a grouped request that has not been submitted yet.
  /datasources/new — Register a database: engine, host, credentials, SSL mode. Reached by: The add action on Datasources.
  /datasources/:id/settings — Per-datasource schema, masking, row security and ER diagram. Reached by: Open a datasource from Datasources.
  /api-connectors/:id/settings — Per-connector schema, permissions, response masking and classification tags. Reached by: Open a connector from API Connectors.
  /api-requests/:id — One API call: request, AI analysis, approval chain, response. Reached by: Open a row in API Requests.
  /reviews?tab=api — The API-requests queue. Reached by: The API-requests tab of the Review queue. The older /api-reviews URL redirects here.
  /deployments/:id — One deployment request: what it releases, its analysis and its decisions. Reached by: Open a row in Deployments.
  /reviews?tab=deployments — The deployment queue; ?tab=rollbacks is the rollback worklist. Reached by: The deployments tab of the Review queue. The older /deployment-reviews URL redirects here.
  /deployment-versions/:pipelineId — The same matrix for one pipeline, plus per-environment history. Reached by: Open a pipeline from Version Matrix.
  /profile — Own account: display name, password, two-factor (TOTP), review delegation while you are away, API keys, Slack account link. Reached by: The user menu behind your avatar, top right.
  /setup — First-run wizard. Shown until an active admin exists. Reached by: Shown automatically on a fresh install; there is no menu entry for it.
  /login — Sign in with password, OAuth 2.0 / OIDC or SAML 2.0 SSO. Reached by: Where anyone who is not signed in is sent.
  /forgot-password — Ask for a password-reset email. Reached by: The forgotten-password link on the sign-in screen.
  /reset-password/:token — Set a new password from the link in that email. Reached by: The link in the password-reset email.
  /invite/:token — Accept an invitation and choose a password. Reached by: The link in the invitation email.
  /admin/groups/:id — One group: its members and the permissions it grants them. Reached by: Open a row in Groups.
  /admin/organizations/:id — One organization and its settings. Reached by: Open a row in Organizations.
  /admin/attestation/:id — One campaign: its scope, progress and evidence export. Reached by: Open a campaign from Attestation.
  /admin/ai-configs/new — Add an AI provider configuration. Reached by: The add action on AI configurations.
  /admin/ai-configs/:id — Edit one AI provider configuration, its prompt and its knowledge base. Reached by: Open a row in AI configurations.
  /admin/deployment-pipelines/:id — One pipeline: environments, permissions, freeze windows, routing policies and the CI snippet. Reached by: Open a pipeline from Deployment Pipelines.

Buttons and fields on the main screens (quote these labels verbatim)
  Query editor (Workflow → Database → Query editor)
    "Datasource" — field. Which database the query runs against.
    "Describe your query" — field. Optional plain-language description the AI turns into SQL.
    "Generate query" — button. Writes a draft query from that description.
    "Format" — button. Reformats the SQL in the editor.
    "Templates" — button. Opens the saved query templates.
    "Save as template" — button. Saves the current query as a template.
    "Justification" — field. Why the query is being run.
    "· required for review" — note. Sits beside the Justification label: a query that goes to a reviewer needs one.
    "Why are you running this query?" — placeholder. The prompt inside the empty Justification field.
    "Analyze" — button. Runs the AI risk analysis without submitting anything.
    "Dry run" — button. Asks the database for an execution plan without running the query.
    "Scheduled execution" — field. Optional date and time for the approved query to run automatically.
    "Recurring execution" — field. Optional repeating schedule; it replaces one-time scheduling.
    "Submit for review" — button. Sends the query into the review workflow.
    "Emergency access" — button. Runs immediately, bypassing review — only for someone holding the break-glass permission on that datasource.
    "History" — button. Recent queries submitted from this editor.

  Query history (Workflow → Database → Query history)
    "Search SQL, ID or submitter…" — placeholder. Filters the list by SQL, id or submitter.
    "Status" — column. Where the query stands in the workflow.
    "Risk" — column. The risk rating the AI analysis gave it.

  Query detail (/queries/:id)
    "Justification" — section. The justification the submitter gave.
    "AI analysis" — section. The AI risk score and its explanation.
    "Execution result" — section. Rows affected, duration, and any database error.
    "Execute now" — button. Runs an approved query now.
    "Cancel query" — button. Withdraws a query the submitter no longer wants reviewed.
    "Replay in test environment" — button. Re-submits the same SQL against a test datasource; it re-enters review.
    "Export CSV" — button. Exports the result rows as CSV, subject to the export policy.
    "Export PDF" — button. Exports the result rows as PDF, subject to the export policy.

  Review queue (at the top of the sidebar)
    "All caught up" — empty state. Shown when nothing is waiting on you.
    "Reject" — button. Confirms a rejection; a comment is required.
    "Approve selected" — button. Approves every selected row with one shared comment.
    "Reject selected" — button. Rejects every selected row with one shared comment.
    "Request changes" — button. Sends every selected row back to its submitter.

  Approve or reject (/reviews/:id/decide)
    "Approve" — button. Records an approval and forwards the query to execution.
    "Reject" — button. Records a rejection and notifies the submitter.
    "Confirm your password" — field. Re-authentication before the decision is committed.
    "Authentication code" — field. The one-time code instead, when two-factor is on.
    "You can't review your own query." — message. Shown when the signed-in user submitted the query themselves — nobody reviews their own.

  Profile (/profile)
    "Profile settings" — menu entry. Opens the profile screen, from the avatar menu at the top right.
    "Sign out" — menu entry. Ends the session, from that same menu.
