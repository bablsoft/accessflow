{{- if not .Values.ingress.tls.enabled }}

TLS is disabled on the Ingress. To enable HTTPS, set ingress.tls.enabled=true
and either supply a Secret via ingress.tls.secretName or add a cert-manager
annotation under ingress.annotations.
{{- end }}

{{- else if .Values.route.enabled }}

Visit the application through the Gateway this HTTPRoute is attached to:
{{- range .Values.route.parentRefs }}
  Gateway "{{ .name }}"{{ with .namespace }} in namespace "{{ . }}"{{ end }}{{ with .sectionName }}, listener "{{ . }}"{{ end }}
{{- end }}
{{- if .Values.route.hostnames }}
{{- range .Values.route.hostnames }}
  https://{{ . }}/
{{- end }}
{{- else }}

  route.hostnames is empty, so this route matches EVERY hostname on the parent
  Gateway's listeners, and its "/" rule absorbs any hostname no other route claims.
  Set route.hostnames to scope it to the hosts you own.
{{- end }}

TLS is configured on the Gateway listener, not on the HTTPRoute — this chart cannot
set it. Make sure the listener you attached to terminates HTTPS: /ws carries an
access token in the query string and must not traverse a plaintext listener.

{{- else }}

Neither ingress.enabled nor route.enabled is set. Use kubectl port-forward to reach
the services locally:

  # Frontend (UI)
  kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "accessflow.frontend.fullname" . }} 8080:{{ .Values.frontend.service.port }}

  # Backend (API + WS)
  kubectl --namespace {{ .Release.Namespace }} port-forward svc/{{ include "accessflow.backend.fullname" . }} 8081:{{ .Values.backend.service.port }}

Then open http://localhost:8080
{{- end }}

Backend health endpoints (port {{ .Values.backend.service.port }}):
  /actuator/health           — overall liveness + readiness
  /actuator/health/liveness  — Kubernetes liveness probe target
  /actuator/health/readiness — Kubernetes readiness probe target
  /actuator/info             — build version metadata
